# 冰箱管家课程设计说明

## 1. 项目定位

项目对应课程题目 B6“菜谱 / 冰箱管理”，定位为面向家庭食材记录的本地管理工具。主 App 解决“有什么、何时过期、能做什么”三个问题，伴生模块进一步把库存数据做成可视化看板和可导出的个人数据资产。

项目不使用后端，所有库存、推荐和提醒逻辑均在 Android 设备本地完成。

## 2. 需求对照

| 课程要求 | 项目实现 |
| --- | --- |
| ≥ 4 个界面 | 库存列表、食材编辑、菜谱推荐、菜谱详情，以及独立的看板界面 |
| 列表 → 详情导航 | 菜谱列表点击“查看做法”进入菜谱详情页 |
| 数据持久化 | Room 保存食材名称、分类、数量、过期日期 |
| 硬能力 | WorkManager 后台周期任务、系统通知、跨 App ContentProvider |
| 异步与生命周期 | ViewModel + StateFlow + 协程 + `repeatOnLifecycle` |
| 权限和降级 | Android 13 通知权限拒绝后库存与推荐仍可使用，并显示提示 |
| 自定义业务逻辑 | 别名匹配、库存覆盖率、临期奖励组成的本地菜谱推荐算法 |
| 加载 / 空 / 错误态 | 主库存页和数据看板均具备完整状态切换和重试入口 |
| 伴生模块 | `dashboard` 独立 App，可独立启动，通过 Provider 读写主 App 数据 |
| Git 记录 | 按构建修复、库存、通知、推荐、详情、状态、接口、伴生模块、图表、导出、测试、文档拆分提交 |

## 3. 功能结构

### 3.1 主 App

1. 库存列表
   - 按过期日期升序展示。
   - 标记“新鲜”“N 天后过期”“已过期”。
   - 展示总种类、临期数、过期数。
2. 食材编辑
   - 新增和编辑复用同一个界面。
   - 名称、分类、数量、日期均有校验。
   - 日期通过系统 DatePicker 选择。
3. 过期提醒
   - 每天生成唯一周期任务。
   - 通知摘要列出过期和临期食材名称。
   - 点击通知返回库存页。
4. 菜谱推荐
   - 读取当前有效库存。
   - 支持常见别名。
   - 按匹配度和临期优先程度排序。
5. 菜谱详情
   - 展示适配度、已有食材、缺少食材和制作步骤。

### 3.2 伴生模块

1. 独立显示库存汇总。
2. 绘制新鲜、临期、过期三段环形图。
3. 导出 CSV 到用户选择的位置。
4. 批量删除已经过期的食材。
5. 主 App 不可用时给出错误信息、重试和跳转入口。

## 5. 数据库设计

表名：`food`

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INTEGER | 主键，自增 | 食材 ID |
| name | TEXT | 非空（业务层校验） | 食材名称 |
| type | TEXT | 非空（业务层校验） | 分类 |
| count | INTEGER | 大于 0（业务层校验） | 数量 |
| expireDate | TEXT | `yyyy-MM-dd` | 过期日期 |

日期使用 ISO 格式字符串，便于 SQLite 直接排序，也能通过 `SimpleDateFormat` 严格解析。解析失败时页面显示“日期有误”，不会导致应用崩溃。

## 6. 关键实现

### 6.1 生命周期与状态

`FoodViewModel` 将 Room Flow 映射为 `InventoryUiState`：

- `Loading`：首次读取或重试时显示进度条。
- `Content`：更新列表、空态和库存汇总。
- `Error`：显示错误信息与“重试”按钮。

Activity 使用 `repeatOnLifecycle(STARTED)` 收集状态，页面不可见时停止收集，避免无效更新。

### 6.2 临期判断

将当前时间和过期日期都归一化到自然日零点，再计算相差天数：

- 差值小于 0：已过期。
- 差值在 0 到 7 之间：临期。
- 其他：新鲜。

日期解析使用非宽松模式，`2026-02-31` 会被拒绝。

### 6.3 菜谱推荐

推荐算法不依赖云端：

1. 为每道菜定义必需食材、可选食材和别名。
2. 将食材名称与别名做包含匹配。
3. 计算必需食材覆盖率。
4. 可选食材逐项加 0.03。
5. 匹配到临期或过期食材时加 0.12，引导优先消耗。
6. 按主要食材是否齐全、总分、匹配数量排序。

该算法可解释，课堂演示时能直接说明某个推荐为什么排在前面。

### 6.4 定时通知

- 使用唯一周期任务 `daily_expiry_scan`，周期为 1 天。
- 应用启动时重新登记任务，保证任务链存在。
- 首次提醒目标时间为次日 09:00，但不是精确闹钟，系统可能延迟执行。
- “立即检查”使用一次性唯一任务，适合课堂演示。
- 固定通知 ID 可以避免每天堆叠大量重复通知。

### 6.5 跨 App 数据共享

主 App 暴露 `content://com.fridge.fridgeapp.provider/food`。

- 读权限：`com.fridge.fridgeapp.permission.READ_FOOD_DATA`
- 写权限：`com.fridge.fridgeapp.permission.WRITE_FOOD_DATA`
- 保护级别：`signature`

看板不直接访问主 App 的 SQLite 文件。两个 Debug App 自动使用同一调试签名；发布时也必须使用同一正式签名。

## 7. 权限与兼容性

| Android 版本 | 处理 |
| --- | --- |
| 8.0–12 | 自动创建通知渠道，无需运行时通知权限 |
| 13+ | 动态申请 `POST_NOTIFICATIONS` |
| 用户拒绝通知权限 | 扫描和库存功能继续工作，页面提示无法显示提醒 |
| 主 App 未安装 | 看板显示连接错误，提供重试和打开主 App 入口 |
| 导出失败 | 显示 Snackbar，不退出看板 |

## 8. 测试

当前自动化检查：

```powershell
.\gradlew.bat :app:testDebugUnitTest :dashboard:testDebugUnitTest
.\gradlew.bat :app:assembleDebug :dashboard:assembleDebug
```

覆盖点：

- 过去日期、未来日期、非法日期。
- 菜谱主要食材齐全。
- 食材别名匹配。
- 临期食材优先标记。
- 看板日期计算。
- CSV BOM、表头、逗号、双引号与公式注入转义。

建议手工验收：

1. 添加今天、7 天后、8 天后和昨天四个日期。
2. 检查列表状态颜色和首页统计是否一致。
3. 拒绝通知权限，确认库存仍可操作。
4. 用“立即检查”触发通知，再检查通知内容。
5. 添加西红柿、鸡蛋，确认“番茄炒鸡蛋”排在推荐前列。
6. 打开看板，检查统计与主 App 一致。
7. 导出 CSV 并用 WPS 或 Excel 打开。
8. 在看板清理过期食材，返回主 App 确认数据同步删除。

## 10. 已知限制与后续方向

- 当前菜谱库为本地静态集合，可扩展到 JSON 导入。
- WorkManager 受系统省电策略影响，不是秒级定时器。
- 两个 App 发布时必须保持同一签名。
- 可继续增加条码扫描、食材图片、分类筛选和云备份。
