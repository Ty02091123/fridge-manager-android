# 代码问答要点

## 为什么使用 Room，而不是直接写 SQLite？

Room 在编译期生成 DAO 实现和 SQL 校验，实体字段与表结构一致，Flow 查询可以直接驱动 UI 更新，同时减少手写 Cursor 的错误。

## 为什么 Activity 不直接调用 DAO？

Activity 只负责界面与导航。ViewModel 持有 Room Flow 并转换为 UI 状态，Activity 在 `repeatOnLifecycle(STARTED)` 中收集，页面停止时自动停止观察。

## 为什么工作管理器选择 WorkManager？

过期扫描不要求秒级精准，WorkManager 可以在设备重启后保留任务，并自动处理省电策略。精确闹钟需要额外权限，还会增加耗电，不适合本场景。

## 为什么 Android 13 拒绝通知权限后应用仍可用？

通知只是在扫描完成后的展示层。扫描、库存、菜谱推荐均不依赖 `POST_NOTIFICATIONS`。拒绝权限时仅隐藏系统通知并显示提示。

## 为什么伴生模块不直接读 Room 文件？

Android 每个应用有独立沙箱，直接读取其他应用数据库不稳定且不安全。ContentProvider 是系统提供的跨进程数据接口，并通过签名权限限制调用方。

## 为什么使用签名权限？

看板需要读写主 App 数据，但这不应向任意应用开放。`signature` 权限只授予与主 App 签名一致的安装包，适合课程中的两个同源 App。

## 推荐算法如何避免“随便推荐”？

推荐结果必须至少匹配一个必需食材；完整匹配优先；库存覆盖率占主要分数；使用临期食材会增加排序分。因此推荐结果能追溯到具体库存。

## 为什么 CSV 要加 BOM？

UTF-8 BOM 能提高 Excel 和 WPS 对中文表头与内容的识别率。同时 CSV 会转义双引号、逗号和以 `= + - @` 开头的公式文本，降低表格公式注入风险。

## 为什么库存有 Loading 和 Error 状态？

数据库打开或迁移可能失败。只有成功读取后才展示空态，避免把“读取失败”错误显示成“冰箱为空”。错误状态提供重试入口。
